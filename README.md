# 年糕家的小饭桌

> 把家里会做的菜做成菜单，家人像在餐厅一样点单，掌勺的人照着做。
> 一个给自己家用的微信小程序，不追求功能多，只解决「今天吃什么」这一个真问题。

## 为什么做这个

家里每天都要回答同一个问题：**今天吃什么？**

真正难的从来不是"吃什么"，而是三个具体的痛点：

- 掌勺的人不知道大家想吃什么，做完了没人吃
- 家里人提需求靠喊，转头就忘
- 想出去吃的时候，翻遍聊天记录也找不到那家店叫啥

这个小程序把这三件事收进一个地方：**点菜 → 提交 → 掌勺的看到**。附带一个「大家喜欢的餐厅」，收藏常去的店，点一下直接导航。

它不解决餐饮经营问题，没有支付、没有订单履约，也不需要营业执照。

## 功能

### 点菜主流程

| 步骤 | 做什么 |
|---|---|
| 选身份 | 点左上角选「我是谁」，点单会署这个名 |
| 翻菜单 | 横向滑动分类（荤菜/素菜/汤/主食/凉菜/喝的），卡片带图片或 emoji |
| 点菜 | 卡片右侧 ＋/− 步进器，选中后才出现辣度选择，避免列表拥挤 |
| 提交 | 确认页可改数量、选份量、写备注（「少放盐」「多放辣」） |
| 汇总 | 提交后生成点菜单，掌勺的人打开就能看到谁点了什么 |

### 菜品管理

- 增删菜品、上下架、改分类
- **拍照或从相册上传菜品图**，没图时用 emoji 兜底
- 标签系统：招牌、费时、快手、10 分钟…
- 一键恢复默认的 18 道菜

### 大家喜欢的餐厅

- **logo 上传**：相册/拍照，或选餐饮 emoji
- **地图选点**：`wx.chooseLocation` 标注经纬度
- **一键导航**：`wx.openLocation` 唤起微信内置地图
- 标签（孩子爱吃 / 不辣 / 要排队）、备注、「谁喜欢」成员标记

### 个性化（不用改代码的部分）

| 想改什么 | 在哪里 |
|---|---|
| 家庭名、口号、掌勺人 | 设置页，或 `config/index.js` 的 `family` |
| 主题色 | 设置页点色块，8 套预设即时换肤 |
| 分类、辣度、份量档位 | `config/index.js` |
| 关掉某个功能 | `config/index.js` 的 `features`，共 8 个开关 |
| 家庭成员名单 | 设置页增删 |

## 技术架构

```
┌─────────────────────────────────────┐
│  微信小程序原生（WXML + WXSS + JS）     │
│  5 个页面 · 无框架 · 无自定义组件       │
└──────────────────┬──────────────────┘
                   │
        ┌──────────┴──────────┐
        │  utils/store.js     │  ← 唯一数据出入口
        │  （统一 async 接口）  │
        └──────────┬──────────┘
                   │
      ┌────────────┴────────────┐
      │                         │
  mode: local              mode: cloud
  本地 Storage             微信云开发数据库
  本地文件系统             微信云存储
  单机可用                 全家共享
```

**没有手写后端，也不需要服务器。** 云开发就是后端：数据库、对象存储、CDN 全部托管，免费额度对家庭场景绰绰有余（数据库 2GB / 云存储 5GB / 每天 5 万次读）。

为什么这么选：为 3–6 人的家庭场景自建 Node + MySQL，维护成本远大于收益。如果以后要接第三方 API 或做定时推送，`store.js` 这一层可以把实现换成 `wx.request` **而五个页面一行不用动**。

### 关键设计取舍

| 取舍 | 理由 |
|---|---|
| emoji 作为图片兜底 | 新加一道菜只填名字就能用，不必先找图；照片随时可补 |
| 辣度选中后才出现 | 每道菜都摆四个 chip 会把列表挤烂 |
| 主题色走 CSS 变量 | 页面根节点注入，`setData` 就换肤，不用重新编译 |
| 餐厅存经纬度而非地址字符串 | 地址只是给人看的，经纬度才能唤起地图导航 |
| 图片抽象到 `utils/media.js` | 本地路径和云 fileID 在 `<image src>` 里用法一致，页面不关心图在哪 |

## 项目结构

```
family-menu/                        # ← 导入开发者工具时选这一层
├── app.js / app.json / app.wxss    # 全局配置、主题、权限声明
├── project.config.json
├── sitemap.json                    # 禁止被微信搜索（家庭自用）
├── config/
│   ├── index.js                    # ★ 个性化配置唯一入口
│   ├── dishes.js                   # 初始菜品种子（18 道）
│   └── shops.js                    # 初始餐厅种子
├── utils/
│   ├── store.js                    # 数据层：local / cloud 双模式
│   ├── media.js                    # 图片选择、存储、删除、预览
│   └── util.js                     # 小工具
├── pages/
│   ├── index/                      # 点菜首页（餐厅条 + 分类 + 购物车）
│   ├── confirm/                    # 确认、备注、提交、成功态
│   ├── manage/                     # 菜品管理（增删改、上传图）
│   ├── shops/                      # 餐厅（logo、地图标点、导航）
│   └── settings/                   # 家庭信息、成员、主题色、功能开关
└── images/                         # 可选：批量预置的菜品图

tools/                              # 电脑上跑的 Node 脚本，不进 family-menu/
├── preflight.js                    # 上传前自检
├── upload.js                       # miniprogram-ci 命令行上传
├── package.json
└── README.md
```

> ⚠️ `tools/` 里的脚本是 Node 程序（首行 `#!/usr/bin/env node`），**不要放进小程序项目目录**，否则开发者工具会把它们当页面 JS 编译并报语法错。

## 快速开始

### 1. 本地跑起来

1. 微信开发者工具 → **导入项目** → 选择 `family-menu` 目录（有 `app.json` 的那层）
2. AppID 填你自己的小程序 AppID
3. 编译，模拟器里就能点菜

首次打开会用 `config/dishes.js` 里的 18 道菜作为初始菜单。

### 2. 让全家人共享数据（重要）

默认 `mode: 'local'`，**数据只存在各自手机里，家人互相看不到**。真要用起来必须切云模式：

1. 开发者工具顶部点「云开发」→ 开通 → 建环境 → 复制**环境 ID**
2. 云开发控制台 → 数据库 → 建 4 个集合，权限全部设为「所有用户可读写」：

```
fm_menu      菜单
fm_order     点单记录
fm_setting   家庭设置
fm_shop      餐厅收藏
```

3. 云开发控制台 → 存储 → 权限设为「所有用户可读」
4. 改 `config/index.js` 两行：

```js
mode: 'cloud',
cloudEnv: '你的环境ID',
```

5. Ctrl+S 重新编译，点 ＋ 加一道菜，回数据库看是否出现记录

### 3. 真机验证

模拟器的地图选点不可用，**必须用手机预览**。

用开发者工具「预览」扫码，依次验证：点菜 → 提交 → 传菜品图 → 加餐厅选位置 → 点导航。

### 4. 发布体验版

1. 工具右上角「上传」→ 版本号 `1.0.0`
2. mp.weixin.qq.com → 管理 → 版本管理 → 开发版本「**选为体验版**」
3. 管理 → 成员管理 → 体验成员 → 添加家人微信号（个人主体上限约 15 人）

家人扫码进入后，右上角「···」→「添加到我的小程序」+「添加到桌面」，以后从微信首页下拉就能直接进，不用再扫二维码。

## 隐私协议：不做这一步，图片和地图是坏的

相册、摄像头、位置都属于隐私接口。必须在小程序后台配置：

**设置 → 服务内容声明 → 用户隐私保护指引**，勾选：

- 相册（仅写入）—— 上传菜品照片和餐厅 logo
- 摄像头 —— 拍照上传
- 位置信息 —— 标注餐厅位置并导航

未配置时调用会返回 **errno 112**，且界面静默无反应。代码侧的 `app.json` 已经声明了 `permission.scope.userLocation` 和 `requiredPrivateInfos`，但**后台那一步只能手动做**。

## 命令行上传（可选）

用图形界面点「上传」最简单，不需要密钥。只有想用命令行/CI 时才走这条路：

```bash
cd tools
npm install

# 后台 → 开发管理 → 开发设置 → 小程序代码上传 → 生成密钥
# 下载后改名 private.key，放在 tools/ 目录
# 同页配置 IP 白名单，或关闭白名单

node preflight.js
MP_APPID=wx你的appid node upload.js upload
```

`preflight.js` 会检查：appid 是否为占位值、页面文件是否齐全、位置权限是否声明、云环境是否填写、代码包是否超 2MB。

## 配置速查

`config/index.js` 是唯一的个性化入口：

| 字段 | 作用 |
|---|---|
| `mode` / `cloudEnv` | 数据存本地还是云端 |
| `theme` | 7 个色值，改一行全局生效 |
| `family` | 家庭名、口号、掌勺人 |
| `categories` | 菜品分类，可增删 |
| `options.spicy` / `persons` | 辣度和份量档位 |
| `features` | 8 个功能开关（辣度、描述、标签、备注、份量、步进器、菜品图、餐厅区） |
| `text` | 按钮和提示文案 |
| `shops` | 餐厅模块标题、常用标签 |

菜品和餐厅数据本身不用改代码，在小程序界面里增删改即可；`config/dishes.js` 和 `config/shops.js` 只是首次打开的种子数据。

## 已知取舍

- **云数据库集合权限是「所有用户可读写」**：体验版阶段没问题（只有 15 个体验成员能进）。正式发布前应收紧为「仅创建者可读写」或接云函数。
- **「我是谁」只是本地存的名字**：家庭场景够用，要防冒充需要接 `wx.login` 拿 openid。
- **切换 local → cloud 不会迁移旧数据**：建议从零开始就直接用 cloud 模式。
- **代码上传密钥只能下载一次**：丢失需重置，旧的立即失效。
