# 家里点菜 · 微信小程序

把家里「会做的菜」做成菜单，家人像在餐厅一样点，掌勺的人照着做。

- 不用餐饮资质、不用支付、不用备案经营类目 —— 属于个人主体的「工具」类目
- 零后端可跑（数据存本机），也能一键切微信云开发（全家看同一份）
- 菜品、分类、主题色、文案、成员，全部在配置文件里改，不用碰页面代码

---

## 一、30 秒跑起来

1. 打开「微信开发者工具」→ 导入项目
2. 目录选 `family-menu` 这一层（有 `app.json` 的这层）
3. AppID 填你自己的，或者先点「测试号」
4. 编译，就能点菜了

首次打开会用 `config/dishes.js` 里的 18 道菜作为初始菜单。

---

## 二、改成你自己家的

**日常调整全在 `config/index.js` 这一个文件里：**

| 想改什么 | 改哪里 |
|---|---|
| 家庭名、一句话、掌勺人 | `family.name` / `family.slogan` / `family.chef` |
| 分类（荤菜/素菜/汤…） | `categories` 数组，增删都行，`id` 别重复 |
| 辣度档位 | `options.spicy`，设成 `[]` 整个辣度选择器消失 |
| 份量档位 | `options.persons` |
| 主题色 | `theme.primary`（想更省事就直接在 App「设置」页点色块） |
| 关掉不要的功能 | `features` 里对应项设 `false` |
| 按钮/提示的措辞 | `text` |

**菜单本身**不用改代码 —— App 里点「菜品」进去就能加、改、删、上下架。

`config/dishes.js` 只是初始种子，改完之后以 App 里的实际数据为准。

### 菜品照片：直接在 App 里传

不用改代码了。「菜品管理」→ 点任意一道菜 → 「菜品图」那一格点一下 → 拍照或从相册选。

- `mode: 'local'` → 图片存在这台手机上
- `mode: 'cloud'` → 自动上传到云存储，**全家看到同一张**

也可以批量预置：图片放 `images/`，数据里加 `image: '/images/xxx.jpg'`。

彻底不想用图片（只用 emoji）：`features.showDishImage = false`。

### 大家喜欢的餐厅

首页 hero 下面有一条横向卡片，点卡片直接打开地图导航。

进「全部」页可以：

- **加一家餐厅**：上传 logo（相册/拍照，或先用 emoji）、地图上选点、打标签（孩子爱吃 / 不辣 / 要排队…）、标注「谁喜欢」
- **改**：点卡片右侧「改」
- **删**：编辑弹层左下「删掉」
- **导航**：点「导航」直接 `wx.openLocation` 唤起微信内置地图

餐厅数据存在 `fm_shop` 集合（云模式）或本机（local 模式），种子数据在 `config/shops.js`。

想关掉整个区块：`features.showShops = false`。

### 位置与隐私：这一步不做，选图和选位置会直接失败

小程序调相册、相机、位置都属于**隐私接口**。从 2023 年起，必须在小程序后台配置：

1. 登录 mp.weixin.qq.com → 设置 → **服务内容声明 → 用户隐私保护指引**
2. 勾选并填写：
   - **相册（仅写入）** / **摄像头** —— 用于上传菜品照片和餐厅 logo
   - **位置信息** —— 用于标注餐厅位置并导航
3. 提交后等审核通过（一般几小时）

没配就调 `wx.chooseMedia` / `wx.chooseLocation`，会返回 **errno 112**（api scope is not declared in the privacy agreement）。

代码侧已经配好的是 `app.json`：

```json
"permission": {
  "scope.userLocation": { "desc": "用来标注常去的餐厅位置，方便导航过去" }
},
"requiredPrivateInfos": ["chooseLocation", "getLocation"]
```

这两项不用你改，但**后台的隐私指引必须自己去配**。

## 三、让全家人真的用起来（重要）

默认 `mode: 'local'`，数据只存在**各自手机**里 —— 你点了什么，掌勺的那台手机看不到。

**要真正一家人用，必须开云开发：**

1. 开发者工具里点「云开发」→ 开通（免费额度足够家庭用）
2. 记下环境 ID，比如 `family-menu-8gxxxxxx`
3. 打开 `config/index.js`，改两行：
   ```js
   mode: 'cloud',
   cloudEnv: 'family-menu-8gxxxxxx',
   ```
4. 云开发控制台 → 数据库 → 建四个集合：
   - `fm_menu`
   - `fm_order`
   - `fm_setting`
   - `fm_shop`
5. 四个集合的权限都选「**所有用户可读写**」（自家用，够了）

> 想只自己一个人用（比如掌勺的给自己记账），`mode: 'local'` 就够，不用开通任何东西。
>
> 开了云开发之后，**菜品照片和餐厅 logo 也会自动传到云存储**，全家都能看到同一张图。local 模式下图片存在各自手机里，别人看到的会是 emoji 兜底。

改完重新编译，之后谁点的菜，全家都看得到。

## 四、不用开发者工具上传（命令行）

### 先跑自检

```bash
node preflight.js
```

会检查：appid 是否还是占位值、页面文件是否齐全、位置权限是否声明、云环境是否填了、代码包是否超 2MB。有 ❌ 就先改，改完再传。

### 一次性准备

1. 小程序后台 → 管理 → **开发管理 → 开发设置 → 小程序代码上传**
2. 生成「代码上传密钥」→ 下载，重命名成 `private.key`，放到本目录
3. 同一页配置 **IP 白名单**（或点「关闭 IP 白名单」，自家项目风险可控）

### 上传

```bash
npm install
MP_APPID=wx你的appid node upload.js upload
```

想先看二维码再决定：

```bash
MP_APPID=wx你的appid node upload.js preview
# 生成 preview.jpg，用手机扫
```

可选环境变量：`MP_VERSION`（版本号）、`MP_DESC`（备注）、`MP_ROBOT`（1-30）。

上传成功后 → 小程序后台 → 管理 → 版本管理 → 把「开发版本」**选为体验版**。

## 五、发给家人

体验版不需要审核，两件事就够：

1. 后台「版本管理」里选为体验版 → 得到二维码
2. 「管理 → 成员管理 → 体验成员」把家人的微信号加进去

个人主体体验成员上限约 15 人，一家人完全够。

> 体验版不能被搜索到，家人从分享卡片或扫码进入。想搜名字就进，得走正式发布（要改小程序名称 + 类目 + 备案变更）。

### 体验版 vs 正式版：建议先发体验版

| | 体验版 | 正式版 |
|---|---|---|
| 要不要审核 | 不用 | 要（0.5–1 个工作日） |
| 要不要改名 | 不用 | **必须改**——叫「英语自然拼读助手」但内容是点菜，会被判名称与内容不符 |
| 要不要改类目 | 不用 | 要改成「工具-备忘录」或「工具-效率」 |
| 要不要改备案 | 不用 | **要**，备案信息里的名称必须和小程序名称一致 |
| 家人怎么进 | 扫码 / 分享卡片 | 搜名字 |

**所以：先用体验版跑通、让家里人真用几天，确认没问题再走正式发布。** 正式发布那套（改名 + 改类目 + 变更备案）一次性成本不低，而且个人主体一年只有 2 次改名机会。

## 六、目录结构

```
family-menu/
├── config/
│   ├── index.js       ← 个性化配置（改这里）
│   ├── dishes.js      ← 初始菜品种子
│   └── shops.js       ← 初始餐厅种子
├── utils/
│   ├── store.js       ← 数据层，local / cloud 双模式
│   ├── media.js       ← 图片选择、存储、删除、预览
│   └── util.js
├── pages/
│   ├── index/         ← 点菜首页（餐厅条 + 分类 + 卡片 + 购物车）
│   ├── confirm/       ← 确认、备注、提交
│   ├── manage/        ← 菜品管理（增删改、上下架、传图）
│   ├── shops/         ← 大家喜欢的餐厅（logo、地图标点、导航）
│   └── settings/      ← 家庭名、成员、主题色、开关、历史单
├── images/            ← 想批量预置菜品图就放这
├── app.js / app.json / app.wxss
├── preflight.js       ← 上传前自检（先跑这个）
├── upload.js          ← 命令行上传（miniprogram-ci）
└── package.json
```

## 七、几个设计取舍，说明一下

- **为什么默认用 emoji 而不是图片**：新菜加进来只填个名字就能用，不用先去找图。照片随时能补上，emoji 是兜底不是限制。
- **为什么图片走一层 `media.js`**：local 存本地路径、cloud 传云存储返回 fileID，两者在 `<image src>` 里用法一样。页面不知道也不该知道图到底在哪，以后换成自己的 CDN 只改这一个文件。
- **为什么餐厅要存经纬度而不是存地址字符串**：地址字符串没法导航。存了经纬度才能 `wx.openLocation` 一键唤起地图，地址只是给人看的。
- **为什么辣度只在选中后才出现**：列表里每道菜都摆四个辣度 chip，会挤得没法看。点了才需要选。
- **为什么数据层要抽象**：`store.js` 是一层薄封装，以后想接自己的服务器、换成别的后端，只改这一个文件，五个页面一行不用动。
- **为什么主题色能实时改**：色值走 CSS 变量注入到页面根节点，`setData` 就换肤，不用重新编译。设置页点一下当场就能看到效果。

## 八、常见问题

**Q：点「设置」换了主题色，回首页没变？**
A：设置页点了色块会立刻存，但如果没点「保存设置」，家庭名等其它字段不会存。主题色是即时生效的。

**Q：家人打开是空的？**
A：八成是还在 `local` 模式 —— 各自手机的数据互相看不到。按第三节开云开发。

**Q：上传时报 IP 不在白名单？**
A：报错信息里会给出当前出口 IP，复制到后台白名单里；或者直接关掉 IP 白名单。

**Q：体验版更新了，家人还是旧版？**
A：重新上传后，要在后台「版本管理」里**再选一次体验版**，不会自动更新。

**Q：选图或选位置报 errno 112？**
A：后台「用户隐私保护指引」没配相册/摄像头/位置。见第二节最后一小节。这一步必须去 mp 后台手动配，代码改不了。

**Q：餐厅卡片点「导航」没反应？**
A：这家还没标位置。进「全部」→ 点「改」→ 点「选位置」在地图上定一下。

**Q：云模式下图片传了但家人看不到？**
A：云开发控制台 → 存储 → 权限设置 → 改成「所有用户可读」。

**Q：加了 30 道菜，图片把包撑大了？**
A：图片不走代码包，走本地文件系统或云存储，不影响小程序主包体积（上限 2MB）。放心传。

**Q：想加"今天谁洗碗"这类功能？**
A：可以在 `pages/index` 的 hero 区域加一行文案，或者在 `config/index.js` 里加一个 `extras` 字段做纯展示。要真做成可交互的，跟我说，我加页面。
